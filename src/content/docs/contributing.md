---

説明が分かりにくいところや、紹介したい使い方があれば、ぜひ教えてください！\
パソコンに開発用のソフトを入れなくても、ブラウザーから文章を直せます

## 編集したら、すぐ公開される？

**編集しただけでは公開されません**\
変更案を送ったあと、運営が内容を確認してから正式なガイドへ反映します

| 操作 | 一般の編集者 |
| --- | --- |
| ガイドやソースを読む | できます |
| 自分のコピーで文章を直す | できます |
| 修正案をPRで送る | できます |
| PRにコメントする | できます |
| PRを正式なガイドへ反映する | できません |
| 公開設定や権限を変える | できません |

正式なガイドへの反映は、公開担当の **humisan** が行います
公開設定や権限の変更は、管理者の操作です

一般の編集者にマージ権限を渡す必要はありません\
`main`にはPRと自動チェックを必須にし、反映できる人を`humisan`に限定しています

:::note[公開ガイドとサイトのソースは別です]
この手順で編集するのは、Publicの[hnmt-docs](https://github.com/hnmt-mc/hnmt-docs)です\
トップサイトのPrivateリポジトリを開く必要はありません
:::

## GitHubの言葉を知っておく

| 言葉 | このガイドでの意味 |
| --- | --- |
| リポジトリ | ガイドの文章やファイルをまとめて置く場所 |
| Fork（フォーク） | 自分のアカウントに作る、編集用のコピー |
| ブランチ | 変更ごとに分ける作業場所 |
| Commit（コミット） | 修正内容を保存して、変更の記録を残すこと |
| PR（プルリクエスト） | 「この変更を採用してください」と運営へ送る提案 |
| Review（レビュー） | 提案された内容を確認すること |
| Merge（マージ） | 提案を正式なガイドへ取り込むこと |
| `main` | 現在公開しているガイドの元になるブランチ |

すべて覚えてから始めなくても大丈夫です！\
迷ったら、この表と手順を見ながら進めてください

## すでにある記事を直す

### 1. 編集する記事を開く

直したい記事の下にある **「ページを編集」** を押します\
GitHubで、その記事のファイルが開きます

GitHubのアカウントがない場合は、アカウントを作成してログインしてください\
ガイドへの参加に有料プランは必要ありません

### 2. 自分の編集用コピーを作る

初めて編集するときは、Forkの作成が案内される場合があります\
**Fork this repository**などのボタンから、自分のアカウントにコピーを作ります

すでにForkがある場合は、そのコピーを使えます\
編集画面が開かないときは、[元のリポジトリ](https://github.com/hnmt-mc/hnmt-docs)の **Fork** を押して作成し、自分のコピーから該当するファイルを開いてください

### 3. 文章を編集する

鉛筆のボタン（**Edit this file**）から編集します\
先頭の`---`で囲まれた部分は、記事名や説明の設定です

文章だけを直す場合は、設定部分を残して本文を編集してください\
**Preview**で、見出し・箇条書き・コマンドの表示を確認できます

### 4. 変更を保存する

**Commit changes…**を押し、変更内容を短く日本語で書きます

```text
スポーンへの移動手順を分かりやすくする
```

新しいブランチを作る選択肢がある場合は、変更用のブランチを作ります\
名前は`docs/update-spawn-guide`のように、`docs/`から始めてください

この保存は自分のコピーの変更です\
正式なガイドは、まだ書き換わりません

### 5. PRを送る

**Propose changes**や **Compare & pull request**からPRの画面へ進みます\
表示がない場合は、自分のForkの **Pull requests → New pull request**から作成できます

送り先を確認してください

| 項目 | 選ぶ内容 |
| --- | --- |
| base repository（送り先） | `hnmt-mc/hnmt-docs` |
| base（反映先） | `main` |
| head repository（変更元） | 自分のFork |
| compare（変更したブランチ） | 今回作業したブランチ |

タイトルに「何を直したか」、説明に「なぜ直したか」「どう確認したか」を書きます\
**Files changed**で、自分が変更したファイルだけが含まれているか確認してください

**Create pull request**を押すと、運営へ変更案を送れます！

## 新しい記事を追加する

### 1. 記事を置く場所を選ぶ

自分のForkで、内容に合うフォルダーを開きます

| フォルダー | 掲載する内容 |
| --- | --- |
| `src/content/docs/start/` | 初参加の案内、最初にすること |
| `src/content/docs/life/` | ホーム、移動、会話などの便利機能 |
| `src/content/docs/town/` | 町への参加、TownyChat、お店での取引 |

### 2. ファイルを作る

**Add file → Create new file**を選びます\
ファイル名は、英小文字とハイフンを使った`.md`形式にします

たとえば、町の土地を確認する記事なら、`town/check-land.md`のような名前です\
`town/`フォルダーを開いた状態なら、入力する名前は`check-land.md`だけで大丈夫です

### 3. 記事名・説明・本文を書く

先頭には`title`と`description`が必要です\
次は、既存のホーム案内を短く書いた記入例です

```markdown
---
title: ホームを使う
description: 今いる場所をホームに登録する手順
---

よく訪れる場所を登録すると、あとから戻りやすくなります！

## 登録する

1. 安全な足場の上に立ちます
2. `/home`で管理画面を開きます
3. 解放済みのエンダーアイをクリックします

ボーダーの外など、安全でない場所には登録できません
```

新しい記事では、掲載したい機能の内容に書き換えてください\
画面で選ぶ項目、入力するコマンド、操作後の結果まで書くと、初めての人にも伝わります

保存したあと、既存記事の修正と同じ手順でPRを送ります\
記事が採用されると、置いたフォルダーに合わせてメニューにも表示されます

## PRを送ったあとは

1. 自動チェックが、リンクやファイルの形式を確認します
2. 運営が、文章と実際の操作内容を確認します
3. 修正のお願いがあれば、同じブランチで直して保存します
4. 運営がマージすると、自動公開が始まります
5. 公開が成功すると、サイトの記事が更新されます

**自動チェックが緑になっても、まだ採用・公開されたわけではありません**\
一般の編集者は、マージ操作を行わずに運営の確認を待ってください

修正するときに新しいPRを作り直す必要はありません\
同じブランチに保存すると、開いているPRへ追加の変更が反映されます

## 困ったときは

| 状況 | 対応 |
| --- | --- |
| 編集ボタンが見つからない | GitHubにログインし、自分のForkのファイルを開きます |
| 「変更がない」と表示される | 保存できているか、変更元のブランチを正しく選んでいるか確認します |
| 自動チェックが赤い | PRのChecksから内容を確認します 分からなければ、そのPRにコメントしてください |
| マージボタンを押せない | 一般の編集者では正常です 運営が反映します |
| ファイルが競合している | 無理に上書きせず、PRにコメントして運営へ相談してください |
| マージ後も記事が変わらない | 公開処理と表示への反映に少し時間がかかる場合があります 少し待って再読み込みしてください |

文章を直すのが難しければ、[Issues](https://github.com/hnmt-mc/hnmt-docs/issues)から「どの記事の、どこが分かりにくいか」を伝えるだけでも大丈夫です！

## 書くときに大切にしたいこと

- 実際に使える手順を、初めての人にも分かる言葉で書く
- 権限や設定によって変わる操作は、その条件を書く
- 「。」を多用せず、自然で明るい文面にする
- 個人情報、非公開の設定や管理画面、秘密情報を載せない
- 外部の画像や文章を使う場合は、掲載してよいものか確認する
- GitHubには公開してよい表示名を使い、メールアドレスの非公開設定も確認する

開発環境での確認やブランチの詳しいルールは、[CONTRIBUTING.md](https://github.com/hnmt-mc/hnmt-docs/blob/main/CONTRIBUTING.md)にまとめています
